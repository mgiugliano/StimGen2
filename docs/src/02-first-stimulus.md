# A first stimulus {#sec:tut-first}

This chapter introduces waveforms: segments, durations, generators, and
units. All examples are complete `.sg` files.

## A current step

The simplest stimulus is a step:

```
# step.sg: a 1 s depolarising step
500ms  dc(0)
1s     dc(300)
500ms  dc(0)
```

Each line is a *segment*. It starts with a duration and continues with what
the output does during that time. `dc(level)` holds a constant level. The
segments are played one after the other, so this waveform lasts 2 s.
Everything after a `#` is a comment. @Fig:step shows the result.

The waveform does not say whether 300 means picoamperes or millivolts. That
is decided by the channel it is played on (@sec:tut-multichannel). We may
still write the unit, as in `dc(300pA)`, and StimGen 2 will check that it
matches the channel.

![The step waveform of `step.sg`, rendered by `sg` at 20 kHz. Dotted lines mark the boundaries of the three segments.](figures/fig-step.pdf){#fig:step}

### Durations and units

Durations are written with a unit: `500ms`, `1s`, `2min`, `250us`. The unit
of a segment duration is required, so `1 dc(0)` is an error. For other
parameters a number without a unit is in the canonical unit (seconds,
hertz, radians), but we recommend always writing the unit: frequencies in `Hz` or `kHz`, phases in
`rad` or `deg`, and times in `s`, `ms`, or `us`. Writing the wrong kind of
unit, such as a frequency of `10ms`, is an error, not a guess
(@sec:units).

### Negative values

Negative numbers need no special care:

```
500ms  dc(0)
1s     dc(-100)
500ms  dc(0)
```

## Generators and their parameters

`dc` is one of sixteen *generators* listed in @sec:primitives. A generator
takes parameters, given by position or by name:

```
5s  sine(50, 8Hz)                       # by position
5s  sine(amp=50, freq=8Hz)              # by name, same thing
5s  sine(50, 8Hz, phase=90deg, offset=10)
```

Parameters that are not given take their default values, listed in the
card of each generator. For example, `phase` and `offset` of `sine` default
to zero. Naming parameters makes a file easier to read later, and we use
names in most examples.

A few generators of everyday use:

```
2s    ramp(from=0, to=500)              # linear ramp
5s    square(amp=100, freq=2Hz, duty=25%)
10s   chirp(amp=50, f0=0.5Hz, f1=20Hz)  # frequency sweep (ZAP)
200ms biexp(amp=30, tau_rise=1ms, tau_decay=8ms)   # synaptic-like current
```

## Noise

Noise stimuli are generated by stochastic generators. The most common is the
Ornstein–Uhlenbeck process `ou`, a Gaussian noise with a given mean,
standard deviation, and correlation time. It is often used to mimic the
synaptic bombardment a neuron receives in vivo:

```
1s   dc(0)
10s  ou(mean=100, sd=50, tau=5ms)
1s   dc(0)
```

Each time this file is played, the noise is a new realisation with the same
statistics. To present exactly the same noise again, give it a seed:

```
10s  ou(mean=100, sd=50, tau=5ms, seed=17)
```

Any segment with `seed=17` and the same parameters produces the same
samples, today or in ten years, on any computer (identical to the last
digit of floating point in the strictest case, @sec:repro-levels). Even without a seed, the
seed that was actually used is stored with the data, so no realisation is
ever lost (@sec:stochastic).

Other noise generators are `wnoise` (Gaussian white noise), `unoise`
(uniform white noise), and `cnoise` (noise with a $1/f^\alpha$ spectrum).

## Pulse trains

Trains of brief pulses are used to evoke spikes or to stimulate synapses.
The generator `pulses` covers regular and random trains:

```
1s    dc(0)
500ms pulses(amp=2000, rate=20Hz, width=1ms)                 # 10 pulses
1s    dc(0)
2s    pulses(amp=2000, rate=20Hz, width=1ms, timing=poisson)  # random times
```

The first train has pulses exactly every 50 ms, starting at the beginning of
its segment. The second has the same mean rate, but the pulses occur at
random times, as in a Poisson process. Every pulse of a train has exactly
the same number of samples, which is what an experimenter expects
(@sec:prim-pulses).

The shape of the pulses can be changed: `shape=exp` gives exponentially
decaying pulses, `shape=biexp` synaptic-like pulses, `shape=biphasic`
charge-balanced pulses for extracellular stimulation.

## From description to samples

When a waveform is played or rendered, it is sampled at the rate of the
set-up. Each segment covers the samples that fall within its time interval,
and the boundaries are rounded so that rounding errors never accumulate
(@sec:sampling). In everyday use, none of this needs attention. It matters
only when segments last a few samples or less, and then StimGen 2 warns.

A waveform can be checked and rendered from the command line. For example,
with the illustrative tools of @tbl:cli:

```
sg check step.sg
sg render --rate 20kHz step.sg -o step.sgb
sg render --rate 20kHz '500ms dc(0); 1s dc(300); 500ms dc(0)' -o step.sgb
```

The last line shows that a short waveform can also be written directly on
the command line, with segments separated by `;`.
